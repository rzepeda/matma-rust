# MATMA Rust for Antigravity

Use when asked to implement/refactor Rust types, improve tests, or identify impacted tests under MATMA. Load `references/commands.md` on demand.

1. Read the consumer project's own Rust layout; maintain one independent MATMA identity per named Rust type, including types sharing a `.rs` file; allow associated `impl` blocks. Respect all seven governing MATMA rules and report native-language limits.
2. Run `matma-indexer validate --check -o json`, `matma-indexer index -o json` after structural edits; do not run impact against stale manifests.
3. Generate only missing mirrored test/mock stubs with `scaffold`; never overwrite developer files. Explicitly failing generated tests are tasks, not passing coverage.
4. Select tests with `impact --target ... --level ... -o json`. Read only implicated source/manifests/mocks and business/regression registrations to limit context.
5. Verify boundary discipline: unit (one real type), interaction (exactly two real types), business (real domain with infrastructure mocks), regression (real services/datasets). Build trait-based injected doubles in `tests/mocks/mirror/`, not inline in multiple tests.
6. Run chosen `cargo test` commands manually and report real failures or successful executions. Business/regression tests are separate and may need real-service approval. Never claim that `impact` runs tests.
7. Surface source macro/trait/workspace/private-API ambiguities and ask for an architecture decision where rule-preserving implementation is impossible.

When dependencies are circular (A ↔ B), retain the original target in the visited set and do not repeat any settled type. Use `affected_symbols` for test selection and symbol-scoped context; a multi-type file requires a specific symbol target. The Rust private-unit child-module bridge is agreed conceptually but not generated by this CLI version.

**Symbol isolation:** Where A and B share a Rust file, unit test files and centralized mock files are separately mirrored for A and B. Target A by its type identity; never select B merely because it resides in the same file. At higher impact levels, select B only when an actual reverse type dependency exists. Use affected_symbols, not affected_sources, for type-scoped selection. Register business/regression tests against fully qualified types for multi-type files.

# MATMA Rust — Google Antigravity

Apply the owner-approved Rust-specific type-atomic amendment to the seven MATMA rules; multiple Rust types can share one file. **One type is one MATMA identity, independent of physical module co-location.** Read `references/commands.md` when applying the workflow. Do not claim tool execution without terminal/repository access.

1. Inspect the target type and its existing mirrored companions. Run `matma-indexer index -o json` before editing to establish the baseline, then use `context -f Type -o json` to read only the type declaration, associated `impl` regions, dependencies and warnings. Never load unrelated types from the same file by default.
2. Run `matma-indexer scaffold -f Type -o json` for missing mirror companions. It creates marked, `#[cfg(test)]` child-module bridges in the real source module to provide private access in Cargo tests. Never delete developer-authored tests/mocks or change production visibility. Keep all permanent tests and mocks in their deterministic per-type mirrors; migrate temporary inline assertions before completing TDD.
3. Write real assertions; generated test placeholders deliberately panic and must be replaced. Run `matma-indexer validate --check -o json` to detect incorrect bridges and unfinished scaffolds. A validation failure is not completion.
4. MATMA isolation: **unit A = real A, every exercised collaborator mocked**. **Interaction A→B = real A, real B** (if A creates B, exercise that real creation pathway), all other downstream collaborators mocked. **Unit B with creator A = real B from centralized MockA**, with deterministic or changeable state through a real injection seam. A mock cannot be substituted for a hard-coded concrete Rust type without a compatible trait/generic/factory/fixture seam. Do not duplicate A's business logic inside MockA.
5. Traits have their own mirrored contract tests and index entries. Never instantiate a trait or test a contract against mocks; use concrete real implementors, including default trait methods. Review the `implementors` field for coverage; meaningful contract tests must be authored.
6. Run explicitly selected Cargo test filters in the owning library/binary: e.g. `cargo test --lib order_processing::matma_unit_a` or `cargo test --lib order_processing::matma_interaction_a`. Old top-level MATMA external test entrypoints are deprecated. MATMA selects tests; it never executes them itself.
7. After source edits, explicitly `index` again; `changes --level N` compares two indexed type revisions (union of old/new reverse edges) and lists changed symbols and impacted tests. Use `impact -f Type -l N` for a manually chosen changed type. Do not mistake a file SHA change for a type change; cycles are settled once per type, and shared imports do not inherently connect siblings.
8. Keep business and regression tests non-mirrored and explicit. Business: real internal domain, mocked infrastructure boundaries. Regression: real datasets and services, with separate user/environment authorization. Report untested code, unsupported macro/workspace/cfg resolution, inaccessible mock seams, and actual Cargo results.

Installed skills are guidance, not automatic source editing or Cargo execution. The Rust-specific exception and remaining limits are in the repository ADR and its Rust amendments.
